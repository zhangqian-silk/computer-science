# 稀疏注意力：用连接图控制长序列交互

全局 Self-Attention 让每个位置连接所有位置，形成 $n\times n$ 分数矩阵。稀疏注意力预先或动态选择其中一部分边，只在允许的 query-key 对上计算 Attention。它降低连接数量，也同时改变信息能怎样传播。

::: info 符号与约定
沿用[数学与符号约定](../foundations/math-notation.md)。$n,d$ 是序列长度与特征维度，$A\in\{0,1\}^{n\times n}$ 是可见性邻接矩阵，$M$ 是由 $A$ 构造的加性 mask；$Q,K,V$ 沿用 Attention 含义；$k$ 是每个 Query 的平均连接数，$w$ 是局部窗口宽度，$L$ 是堆叠层数。
:::

---

## 稀疏模式就是一个 mask

用邻接矩阵 $A\in\{0,1\}^{n\times n}$ 表示可见性：

$$
M_{ij}=
\begin{cases}
0, & A_{ij}=1\\
-\infty, & A_{ij}=0
\end{cases}
$$

$$
H=
\operatorname{softmax}\left(
\frac{QK^\top}{\sqrt{d_k}}+M
\right)V
$$

数学上，稀疏模式可以通过 mask 描述；工程上若仍先构造完整 $QK^\top$，就没有获得期望的计算节省。实现必须只计算允许的块或边，并与硬件友好的布局配合。

---

## 常见连接图

| 模式 | 每个位置主要连接 | 适合的依赖 | 风险 |
| --- | --- | --- | --- |
| 滑动窗口 | 附近 $w$ 个位置 | 局部连续信号 | 远距传播需多层 |
| 分块 | 同一块或相邻块 | 段落、patch 分区 | 块边界割裂关系 |
| 跨步 / 扩张 | 间隔采样的位置 | 更大感受野 | 可能跳过关键局部边 |
| 全局 token | 少量锚点与所有位置 | 汇总和广播 | 锚点形成带宽瓶颈 |
| 随机连接 | 固定随机边 | 改善图连通性 | 难以解释和优化 |
| 内容路由 | 动态选出的相关位置 | 非局部、输入相关关系 | 选择本身有成本 |

实际模型常组合局部窗口与少量全局边：局部边保证稳定邻域，全局边缩短远距离路径。

### 八个位置的连通例子

对长度为 8 的双向序列，若每个位置只连接左右各 1 个邻居，位置 1 的信息需要经过 7 层接力才能到达位置 8。若增加一个能与所有位置双向连接的全局 token，则路径可以缩短为：

$$
1\rightarrow\text{global}\rightarrow8
$$

只需 2 层即可传播。但全局 token 必须把不同位置的信息压进有限向量，且所有位置都访问它，计算和信息容量会集中到该节点。因果模型还必须保证全局连接不把未来位置的信息泄漏给过去位置。

## 复杂度取决于边数

设每个 query 平均连接 $k$ 个 key，则 score 数量约为 $nk$，主要代价为：

$$
O(nkd)
$$

当 $k$ 与长度无关时，长度项近似线性；若 $k$ 随 $n$ 增长，收益会相应减弱。局部窗口宽度为 $w$ 时，常写为 $O(nwd)$。

理论边数不能直接代表速度。小而不规则的稀疏操作可能比大块密集矩阵更难利用 GPU。比较方案时应同时报告：

- 实际 kernel 是否避免完整矩阵；
- block 大小和稀疏布局；
- 训练与推理的吞吐、延迟和峰值显存；
- 相同任务质量下的成本。

---

## 多层连通性决定表达能力

一层只能沿当前图的边读取信息，多层叠加才形成远距传播。若每层只有半径 $w$ 的局部窗口，$L$ 层后理论感受野约为 $Lw$；但信息还要经过多次非线性与压缩，不等于全局 Attention 的直接连接。

设计稀疏图时应检查：

- 任意两个需要交互的位置是否存在路径；
- 最短路径是否随长度快速增长；
- 因果约束下是否意外引入未来信息；
- padding、分块和文档边界是否被正确处理。

少量全局 token、交错窗口或扩张连接可以缩短图直径，但也会把大量信息集中到少数节点。

## 固定稀疏与动态稀疏

固定稀疏模式只依赖位置，布局可预计算并容易做块化 kernel；缺点是无法根据内容直接跨越图结构。动态稀疏先依据内容选候选 key，表达更灵活，却需要处理选择代价、不可微离散决策或近似检索误差。

动态内容路由不能先计算完整 $QK^\top$ 再取 Top-K，否则选择阶段已经支付了二次成本。常见流程是先用哈希、聚类、低维路由或近似近邻为每个 query 找到较小候选集，再在候选内部计算精确 Attention。

这会引入新的失败层：真正相关的 key 可能在候选选择阶段被漏掉。训练时还要决定路由器是否可微、候选集合变化是否稳定，以及负载是否适合块化计算。评估应同时检查候选召回率和最终任务质量。

低秩 Attention 近似与稀疏 Attention 也应区分：稀疏方法显式删去部分连接，低秩方法则把完整交互压缩到较小中间维度。二者都可能降低复杂度，但保留信息的假设不同。

稀疏 Attention 与检索增强也不同。前者在模型层内选择 token 连接，后者从外部语料取回文档并扩展输入。二者可以组合，但具有不同的数据更新与评估边界。

## 什么时候值得使用

稀疏连接适合以下条件：

- 序列远长于全局 Attention 的经济范围；
- 任务具有明确局部性、分块或少量全局锚点；
- 目标硬件有对应高效 kernel；
- 质量评估能覆盖被删边可能影响的远距关系。

若主要瓶颈是全局 Attention 的访存而不是连接数，FlashAttention 等精确 kernel 可能更直接；若任务依赖任意远距内容交互，固定局部图可能以质量换成本。最终应使用[长上下文评估](../evaluation/long-context-evaluation.md)验证可用长度，而非只报告复杂度。

训练和自回归推理还会呈现不同实现：固定 block-sparse 训练可以批量计算所有允许块；滑动窗口 Decode 只需保留最近窗口内的 KV，能限制缓存增长；带全局 token 的模型还要长期保留对应 KV。动态路由则需要为每个新 query 执行一次候选选择，在线延迟可能由路由而不是 Attention 计算主导。

稀疏规则必须写进模型配置和 cache 语义。窗口大小、块边界、全局位置或哈希规则变化后，已有缓存与新 token 的可见图不再一致，不能继续复用。
