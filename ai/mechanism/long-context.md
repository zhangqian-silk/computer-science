# 长上下文位置扩展：训练长度之外怎样保持位置关系

模型能够接收更多 token，不代表能够可靠使用这些 token。长上下文包含输入容量、位置关系和远距信息利用三个层次；位置扩展处理的是训练长度之外的坐标映射与 Attention 几何。

::: info 符号与约定
沿用[数学与符号约定](../foundations/math-notation.md)。$L_{\text{train}},L_{\text{target}}$ 是训练与目标长度，$s$ 是扩展倍率，$t,t'$ 是原位置与映射位置；$q_i^{(h)},k_j^{(h)}$ 是第 $h$ 个头在位置 $i,j$ 的 Query/Key，$m_h$ 是 ALiBi 头斜率。
:::

## 三个不同问题

| 问题 | 关注点 | 典型手段 |
| --- | --- | --- |
| 输入能否进入模型 | 位置索引、显存和实现上限 | 修改位置配置、缓存管理 |
| 位置关系是否稳定 | 超出训练范围后的 score 几何 | 插值、频率缩放、相对偏置 |
| 模型是否利用远距信息 | 检索、整合与推理能力 | 长序列训练与任务评估 |

位置插值、频率缩放与距离偏置作用于位置关系；远距检索和信息整合能力则需要通过[长上下文评估](../evaluation/long-context-evaluation.md)验证。

---

## Position Interpolation

对采用 RoPE 的模型，一个直接做法是把目标位置压回训练范围。设扩展倍率：

$$
s=\frac{L_{\text{target}}}{L_{\text{train}}}
$$

用 $t'=t/s$ 代替原位置 $t$ 计算旋转。目标区间 $[0,L_{\text{target}}]$ 因而映射到模型熟悉的 $[0,L_{\text{train}}]$。

例如训练长度为 4096，目标长度为 16,384，则 $s=4$：

| 目标位置 $t$ | 插值位置 $t'=t/4$ |
| ---: | ---: |
| 0 | 0 |
| 4096 | 1024 |
| 8192 | 2048 |
| 16,383 | 4095.75 |

整个目标区间被压入原训练坐标范围；与此同时，相邻 token 的位置差从 1 压缩成 0.25。模型不会遇到超范围角度，却必须适应更密集的局部相位。

它避免直接暴露更大的角度，却压缩了相邻位置的相位差。倍率越大，局部位置分辨率损失越明显，通常需要在长序列数据上继续训练以适应新尺度。

## 频率分层缩放

RoPE 的不同维度对应不同波长。统一除以 $s$ 假设所有频段应受到相同缩放，但局部顺序主要依赖高频维度，远距离趋势更多依赖低频维度。

NTK-aware、YaRN、LongRoPE 等路线以不同规则分频处理：

- 保留或少改高频，减少局部能力损失；
- 更强地缩放低频，为远距离提供更慢的相位变化；
- 在过渡频段平滑插值，避免规则突变；
- 配合长序列微调校准新的位置分布。

这些名称背后共同的设计变量是每个频率如何随目标长度改变。比较时应报告具体缩放规则和训练配方，而不能只写「使用 RoPE scaling」。

## ALiBi 的外推方式

ALiBi 不旋转向量，而是在因果 Attention 分数上加入线性距离惩罚：

$$
S_{ij}^{(h)}
=
\frac{{q_i^{(h)}}^\top k_j^{(h)}}{\sqrt{d_k}}
-
m_h(i-j)
$$

推理长度增加时仍使用同一函数，不会出现位置表越界或新的旋转频率组合。这提供了简单的长度外推接口，但远距离分数会受到更大的先验惩罚，实际利用能力仍依赖训练和任务。

## 扩展时还会遇到什么

即便位置关系稳定，长上下文仍会增加：

- prefill 阶段的 Attention 计算；
- KV cache 容量与内存带宽；
- 训练样本的长度和优化难度；
- 关键信息被大量无关 token 稀释的概率。

因此，位置扩展常与[稀疏注意力](./sparse-attention.md)、高效 kernel、KV cache 压缩或检索系统组合。它们处理的是不同瓶颈，不应混写成同一种「长上下文算法」。

训练与部署通常包含不同成本：

1. 修改位置映射或频率规则，使目标索引可计算；
2. 使用包含长依赖的序列继续训练，让模型适应新几何；
3. 检查原长度内能力是否因缩放退化；
4. 部署与训练完全一致的位置配置；
5. 在 Prefill、Decode 和 cache 复用边界上验证 offset。

只有第 1 步时，模型可能可以完成前向，却没有学会利用新长度。继续训练若只把短文档随机拼长，也不必然产生跨段整合信号；数据中需要存在真正依赖远距离内容的目标。

---

## 验收方式

一个位置扩展方案至少应比较：

- 原训练长度内是否退化；
- 不同目标长度上的困惑度或任务准确率；
- 关键信息位于开头、中间、结尾时的曲线；
- prefill 延迟、decode 延迟和 KV cache；
- 是否依赖额外训练，以及额外训练数据长度。

「支持 128K」只是输入上限描述，不能替代这些证据。
