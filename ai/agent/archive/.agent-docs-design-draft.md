# Agent 文档内容设计草案：教科书式组织

状态：临时设计草案，供审阅；模型交互作为先行整理，整体架构尚未迁移。

适用范围：`ai/agent/notes/` 的内容组织及对应导航，不扩展到模型原理、AI Infra 等其他目录。

设计依据：当前 Agent 笔记与本次讨论中确认的学习目标。本稿描述新版文档应该讲什么、按什么关系组织，不是各专题正文，也不代表目录调整已经完成。

---

## 一、设计定位

新版文档面向体系化学习，并兼顾实现理解与面试复述。组织依据是概念之间的前置关系、基本能力的完整性以及方法的层次，不把「出现一个问题，再引入一种解决方案」作为全书统一叙事。

「教科书式」主要体现为：

- 对基本概念、对象、接口和术语给出明确说明。
- 对一项基础能力连续讲清组成、操作、输入输出和处理过程。
- 在基础能力完整之后，系统介绍相关机制、方法分类、性质与适用条件。
- 用例子、图示和练习帮助理解，不要求所有知识都由故障或工程痛点引出。
- 保留知识之间的关联，而不是按照软件组件职责把内容切成互不完整的碎片。

这也不意味着所有章节都必须先展开底层理论。模型交互可以先说明请求和响应，再介绍多轮调用，最后解释生成机制；具体顺序由理解该主题所需的前置知识决定。

### 基础能力应在主文中保持完整

模型交互必须完整包含普通多轮对话、system prompt、历史消息组织以及基础工具调用往返。读者不应为了实现这些能力，被迫到上下文、工具和流程模块中分别寻找缺失步骤。

上下文模块承接这些已介绍的交互对象，系统讲述上下文组织、对话数据存取、压缩、检索与记忆。它不是基础多轮对话实现的归属地。

工具调用同样需要区分层次：模型交互中可以包含一个简单函数的声明、执行与结果回填；工具模块再讲通用工具系统、执行环境和扩展机制。基础例子中的必要参数校验和结果检查不能因此省略。

### 内容完整性优先于严格的「单一归属」

主题应有主要讲解位置，但可以在相关章节保留必要的定义回顾、过程说明或局部例子。避免两种极端：

- 为减少重复，把一个基础能力拆到多个页面，导致任何一篇都无法独立讲清。
- 为追求一篇讲完，把检索、存储、调度、恢复等所有内容塞进同一篇文章。

目标是「主文完整、专题明确、前置关系清楚」，不是固定文章数量或统一篇幅。

### 面向 Agent 知识，不面向 SDK 接入

不提供真实、可运行的代码示例，也不把 SDK 接入作为学习内容或验收条件。调用地址、具体模型名称、鉴权与 API Key 配置、依赖安装、客户端初始化及真实请求发送不进入正文。

「基础能力完整」指概念、信息结构和处理过程连续完整，不等于提供一份能够联网运行的程序。消息列表、提示文本、JSON 数据、图示、数学关系以及必要的简短伪代码可以用于解释知识；它们不扩展成语言绑定、接口接入或工程脚手架教程。

模型交互中的工具往返仍要讲清声明、参数、执行含义和结果回填，但不要求实现一个真实文件读取函数。教科书式的过程推演不以「代码是否成功请求服务」作为学习效果的判断依据。

## 二、整体内容架构

全书采用「总览—六个知识模块—资料与实验」的组织方式。模块表示知识范围；模块主文负责建立完整认识，进阶专题负责展开可以独立学习的方法。

| 模块 | 主干内容 | 可独立展开的专题 |
| --- | --- | --- |
| 模型交互 | 单次调用、多轮消息、基础工具往返与生成机制 | 暂沿用当前完整主文，复杂模型原理引用既有目录 |
| 上下文管理与优化 | 上下文组成、资料组织、对话存取与管理方法 | RAG 与代码检索、长期记忆、上下文压缩 |
| 工具系统与能力扩展 | 工具契约、通用执行、结果表示与能力组织 | 执行环境、MCP、Skills、Hooks 与 Plugins |
| 流程控制与 Agent 方法 | 控制结构、Workflow、Agent Loop 与基本执行过程 | Planning、多 Agent、动态代码编排 |
| Agent 运行时与工程化 | 程序组成、运行状态、任务生命周期与交互控制 | 人工控制、任务恢复、调度接入、安全与隔离 |
| 评测、可观测性与优化 | 验收标准、评测方法、观测信息、实验与改进 | 故障诊断、性能成本、版本回归与发布 |

### 学习前置关系

- 模型交互是主线起点，主文内就应完成单次与多轮交互的基本讲解。
- 上下文管理与工具系统都以模型交互为基础，二者不必形成严格的先后依赖。
- 学习最小 Workflow 和 Agent Loop，需要了解模型调用及基本工具执行，不要求先掌握 RAG、长期记忆、MCP 或上下文压缩。
- 运行时建立在已经理解的模型、上下文、工具和控制方法之上。
- 各章都包含最小结果检查；评测模块再系统介绍评价对象、方法和实验设计。

默认目录可以按表中顺序排列，同时在主文中注明少量真正必要的前置知识。不要把所有进阶专题都列为后续章节的阅读门槛。

### 主文与专题的关系

每个模块应有一个明确的阅读入口，但不强制一个模块只对应一个 Markdown 文件。是否独立成篇取决于主题是否具有完整对象、足够内容和独立学习价值，不提前规定「六篇主干加固定数量的进阶页」。

总览负责展示概念关系与阅读索引，产品实现索引负责定位案例，练习材料负责组织数据分析和过程推演；既有代码材料不作为正文的先修要求。

## 三、各模块的内容设计

### 第一模块：模型交互

学习目标：理解模型调用的输入输出，能够组织单次请求、普通多轮对话和工具结果回传，并解释相关生成设置。

主文保留已确认的三段结构。

1. **单次模型调用。**
	- 最小请求与对应的文本响应。
	- 请求、消息、角色和回答正文的基本含义。
	- 输入中的任务、资料、约束和输出要求。
	- Zero-shot 与 few-shot 的提示结构和示例作用。
	- 文字与图片内容的组合，以及图片证据的解释。
	- 结构化输出及其解析。
	- 工具声明、调用参数、执行语义与返回结果。
	- 流式响应的读取与完整性判断。
	- 调用结果、生成结束与工具执行结果的层次区别。
	- 请求参数和响应字段速查。
2. **多轮模型交互。**
	- 用户对话轮次与模型调用次数。
	- System prompt 与用户消息的配合。
	- 内存中的历史消息维护与连续追问。
	- Assistant 回答如何进入后续输入。
	- 工具调用消息、结果消息及调用 ID 的对应关系。
	- 下一次请求的完整消息示例。
3. **相关基础机制。**
	- Token、聊天模板和自回归生成。
	- Prefill、Decode 与采样参数。
	- 候选分数、概率分布和采样的关系。
	- 上下文窗口和输出预算。
	- KV Cache、前缀缓存与结果缓存的基本区别。
	- 调用延迟与用量，以及输入、缓存、生成和推理 Token 的统计关系。

基础 Prompt 设计、多轮消息实现和最小工具往返均在本模块讲完整。对话数据库、压缩算法、通用工具框架不作为完成本模块学习的前提。

### 第二模块：上下文管理与优化

学习目标：认识上下文的组成、表示和生命周期，理解对话资料的组织、存取、选择与压缩方法。

本模块以已经介绍的消息列表和模型请求为基础，不重新从「如何发送第二轮 user 消息」开始。

建议内容序列：

1. **上下文的组成与表示。** 区分指令、历史消息、外部资料、工具结果和记忆信息，说明它们如何参与当前请求。
2. **资料组织与选择。** 介绍来源、相关性、顺序、去重、版本和预算分配等组织原则。
3. **对话数据与存取。** 介绍会话标识、消息记录、序列化、写入、读取，以及加载历史后重新组成模型输入。
4. **历史管理方法。** 系统介绍保留窗口、选择性保留、摘要、压缩及其信息保真要求。
5. **知识与记忆的使用。** 建立检索资料、会话历史和长期记忆之间的关系，再分别进入专题。
6. **方法评价。** 比较信息覆盖、来源可追溯性、消息完整性、输入长度与任务表现。

建议保留的专题：

- **RAG 与代码检索**：资料表示、索引、召回、排序、证据组装与检索评价。
- **长期记忆**：记忆类型、作用域、写入、召回、更新、冲突与删除。
- **上下文压缩**：裁剪、摘要、压缩与重建的具体方法及验证。

普通对话的存储、读取和会话加载应在这里讲清，不因为使用了数据库就再转移到运行时模块。基础 Prompt 写法继续保留在模型交互；本模块不再与其重复建立一套入门体系。

### 第三模块：工具系统与能力扩展

学习目标：在理解基础工具调用往返之后，掌握工具如何形成可组合、可执行、可扩展的能力集合。

建议内容序列：

1. **工具契约。** 名称、用途、参数、返回值与执行语义；区别模型可见描述和程序执行所需信息。
2. **通用执行过程。** 工具注册、名称分派、参数校验、必要授权、函数执行与结果转换。
3. **结果与错误表示。** 正常结果、未找到、参数错误、拒绝和超时等基本语义。
4. **执行环境。** 文件、进程、浏览器和远程服务的输入输出及资源特点。
5. **能力接入与扩展。** 介绍 MCP、Skills、Hooks 与 Plugins 的对象、接口和组合关系。
6. **进阶执行性质。** 再展开并发、副作用、重试、版本和资源释放等内容。

建议保留执行环境、MCP、Skills、Hooks／Plugins 等独立专题。每篇先讲清自己的对象和基本操作，再介绍完整协议、生命周期或复杂组合。

本模块不必重复一整套模型 API 请求与响应；必要例子可以复用模型交互中的 `read_file`，但重点应转向执行器和工具集合，而不是再次解释 `tool_calls` 字段。

### 第四模块：流程控制与 Agent 方法

学习目标：理解多步任务的控制与数据关系，掌握固定流程和模型参与决策的基本组织方式。

建议内容序列：

1. **控制与数据的基本概念。** 步骤、输入输出、依赖、状态、顺序、分支和循环。
2. **Workflow。** 固定步骤、条件分支、结果传递及一个完整执行示例。
3. **Agent Loop。** 模型决策、工具执行、观察更新、再次调用与终止条件。
4. **方法比较。** 比较下一步由谁决定、状态怎样更新、结果怎样交付，以及两种方式如何组合。
5. **进阶控制方法。** Planning、子任务组织、多 Agent 与动态代码编排。

Workflow 与 Agent Loop 的基础内容适合在同一篇主文中连续讲解，便于建立比较；合并不意味着二者是同一种控制方式，也不意味着 Workflow 是必须升级为 Agent 的低级阶段。

Planning、多 Agent 和动态编排可以保留独立专题。并发调度、产品内部循环、任务重放等实现细节不应打断最小控制过程的讲解。

### 第五模块：Agent 运行时与工程化

学习目标：理解前述能力怎样组成一个运行程序，以及任务在程序中的状态、交互与生命周期。

建议内容序列：

1. **程序的基本组成。** 模型接口、上下文构造、工具执行、控制逻辑和结果检查。
2. **一次任务的运行过程。** 输入接收、任务启动、步骤推进、结果交付和资源释放。
3. **运行对象与状态。** 区分任务、执行尝试、会话、进程及其状态关系。
4. **运行中的交互。** 用户补充信息、人工确认、取消、中断及状态反馈。
5. **持久任务执行。** 任务进度、未完成动作、执行结果和恢复位置的保存与恢复。
6. **调度、隔离与接入。** 多任务管理、执行者接入、资源限制和安全边界。

主文先讲单进程、单任务的完整运行实例，再系统介绍可扩展的运行机制。人工控制、任务恢复、调度接入、安全与隔离按内容深度保留专题。

普通聊天记录的保存和加载仍属于上下文模块。这里的恢复重点是运行过程：例如任务执行到哪一步、工具动作是否已经发生、恢复后哪些步骤仍需继续。

### 第六模块：评测、可观测性与优化

学习目标：建立对模型应用和 Agent 的评价方法，理解观测数据、实验设计和改进结论之间的关系。

建议内容序列：

1. **评价对象与标准。** 回答、工具调用、执行过程、最终任务结果与完成条件。
2. **评测方法。** 规则检查、测试程序、人工评价和模型辅助评价。
3. **数据与实验设计。** 样例集、评价维度、对照实验、重复运行及结果记录。
4. **可观测性。** 日志、事件、Trace、指标及它们在解释执行过程中的作用。
5. **性能与成本。** 输入输出规模、调用次数、延迟、并发、缓存和模型选择。
6. **回归与版本管理。** 变更比较、回归集、发布记录与回退依据。

本模块可以包含排障案例和故障注入，但不以排障作为介绍整个知识体系的唯一入口。主文先把评价对象、方法和实验讲清，复杂故障矩阵与具体平台机制后置。

## 四、核心主题的归属与衔接

这张表用于设计和编辑时协调内容，不要求在每篇正式文档开头反复声明职责。

| 主题 | 主要讲解位置 | 衔接原则 |
| --- | --- | --- |
| 基础输入设计、system prompt、few-shot | 模型交互 | 上下文与评测章节按需要回顾，不重写完整入门教程 |
| 内存历史列表、用户追问、消息回填 | 模型交互 | 多轮能力在本章闭合 |
| 一个简单函数的声明、执行、结果回传 | 模型交互 | 不以通用工具框架作为前置 |
| 对话存储、读取、重新组装与会话加载 | 上下文管理 | 与基础多轮调用保持连续，但不混同于任务恢复 |
| 历史选择、裁剪、摘要、压缩与记忆 | 上下文管理 | 基于已介绍的对话对象讲述方法 |
| 多工具执行器、环境、协议与扩展 | 工具系统 | 复用模型交互的协议认识，展开通用执行能力 |
| 顺序、分支、循环、规划与协作 | 流程控制 | 以模型和工具的基础能力为前置，不要求所有进阶组件齐备 |
| 任务生命周期、运行状态、恢复与调度 | 运行时 | 区分普通历史加载与执行状态恢复 |
| 最小校验与结果检查 | 各章基础例子 | 评测章节再统一展开方法、指标与实验 |
| Token、窗口、缓存的基本概念 | 模型交互 | 上下文讲管理方法，评测优化讲测量与比较，不反复推导同一基础知识 |

「主要讲解位置」不等于其他章节绝对不能出现同一概念。必要回顾有助于完整阅读，重复展开和循环前置才需要消除。

## 五、现有文档的调整方向

以下文件名均指当前 `ai/agent/notes/` 下的资料。本稿只确定内容去向，不立即变更文件路径。

| 现有内容 | 新版调整方向 |
| --- | --- |
| 模型交互主文 | 保留单次调用、多轮交互、基础机制的完整结构，继续维护统一的输入输出示例 |
| `prompt-engineering.md` | 基础任务表达、system prompt 与 few-shot 并入或衔接模型交互；提示对照实验的方法归入评测，不整篇并入上下文入门 |
| `context-engineering.md` | 改为上下文组成、组织、选择和管理的主干，避免一开始铺开版本 manifest 与复杂恢复状态 |
| `conversation-memory.md` | 基础多轮消息实现回归模型交互；对话存取保留在上下文主干，长期记忆作为专题，任务执行状态说明与运行时衔接 |
| `compaction.md`、`rag-retrieval.md` | 保留独立方法主题，按概念、基本过程、方法分类、性质与评价重新组织 |
| `tool-calling.md` | 面向通用工具执行；基础调用往返以模型交互为主，不重复一套 API 入门 |
| 执行环境、MCP、Skills、Hooks／Plugins | 保留独立对象，基本操作前置，版本、并发和产品差异后置 |
| `workflows.md`、`react-loop.md` | 基础内容组织为连续主文；消息协议不重复详讲，控制方式和完整执行过程需要讲清 |
| Planning、多 Agent、动态编排 | 作为流程方法进阶，保留完整主题，不混入最小 Loop 的必读步骤 |
| Harness、人工控制、恢复、调度、安全 | 组成运行时模块；普通对话数据存取不因涉及存储就迁入这里 |
| 评测、可观测性、性能成本、版本发布 | 组成质量模块，先建立评价与实验方法，再进入复杂排障和工程实践 |
| 总览、实现索引、实验、参考资料 | 继续作为导航和配套材料，不另建与正文重复的知识体系 |

产品案例保留可核验的来源与版本信息。短案例可以放在相关机制之后的折叠区；确实具有独立分析价值的长案例再独立成篇，产品实现索引只负责导航。

物理目录、文件合并和重命名应在确认主文结构后逐项决定。迁移时维护站内引用和旧入口，不把一次内容设计同时扩展成全仓库目录重构。

## 六、正式文档的写作与呈现约定

### 内容组织

- 开头直接说明对象和核心概念，不堆砌写作意图、职责声明与范围排除。
- 概念、基本操作、完整例子、方法分类、原理和练习是可选的组织要素，不是每章必须照搬的固定模板。
- 每次引入新概念时，给出足以理解当前内容的定义，不要求读者跨多篇文章补齐一个基本步骤。
- 输入与输出、调用与结果、方法与示例尽量相邻。
- 已经能够形成完整能力的主文，不因出现了其他模块的术语就继续拆分。
- 参数清单、完整消息数据、产品差异和深入讨论可后置或折叠；不以折叠区为由重新加入真实代码或 SDK 接入教程。
- 不反复出现「以下是教学表示」「不是某个真实 API」等提示；通过采用一致的接口、必要的版本说明和明确的例子范围保持准确。

### 示例、信息结构与图示

- 例子用于说明概念与关系，可以使用配置问答、文档检索和只读检查等场景，不强制全书围绕同一个工程故障展开。
- 一个主题内部尽量沿用同一组数据，完整展示关键输入、输出和状态变化。
- JSON 仅用于表达消息、参数与结果的数据关系；伪代码遵循仓库算法风格，不提供可运行的 Go、Python、JavaScript 或其他语言接入示例。
- 不展示调用地址、模型标识、鉴权信息、SDK 安装与初始化；具体字段只在有助于理解信息结构时使用。
- 不因本次整理删除或重写既有代码材料，但不把这些材料搬入主文，也不要求读者先完成 SDK 联调。
- 结构与数据流用简洁图示辅助；消息可见性、调用往返、方法对比等内容优先复用 VitePress 交互组件。
- 图示应突出当前概念，不把所有模块塞进一张总图，也不为每一节机械增加交互组件。

### 概念与实现

- 通用概念和具体产品实现分层描述，不把某个 SDK 字段或框架设计当成普遍定义。
- 实际接口示例保持内部一致，不能在同一过程里无说明地混用多套协议。
- 作者、日期、来源和版本信息保留；涉及真实 API、协议或框架的改写在实施时重新核对一手资料。
- 必要的校验、权限与失败语义跟随基本操作出现；复杂安全分析与故障恢复作为进阶内容系统展开。

## 七、学习与面试的验收方式

正文负责知识讲解，章节练习负责检验理解，不另建重复正文的「面试答案大全」。

| 模块 | 综合能力检查 |
| --- | --- |
| 模型交互 | 构造请求、读取响应，并写出用户追问或工具回传后的下一次输入 |
| 上下文管理 | 说明上下文组成，设计对话记录与存取方式，比较历史保留或压缩方法 |
| 工具系统 | 描述工具契约并推演执行过程，解释参数、结果、错误及扩展接口的关系 |
| 流程控制 | 表达一个固定流程和一个最小 Agent Loop，并解释控制与状态更新 |
| 运行时 | 沿一次任务说明各组成部分、运行状态、交互和结束过程 |
| 评测优化 | 定义验收条件、组织测试样例，并解释对照实验和观测数据 |

练习可以包含概念解释、结构辨析、消息构造、过程推演、方法比较和数据计算，不要求编写真实接入代码。问题情境和异常案例是其中一类题型，不是全书唯一的教学方式。

## 八、后续实施与检查

本文件本身仅是临时设计稿，不作为站点正文发布；各正式文档按确认后的要求独立修订。

后续实施时：

1. 先确认模块内容与主文的完整性，不先固定页数或批量重命名。
2. 逐模块形成主文，再安置进阶专题和产品案例。
3. 检查基础多轮交互与工具往返是否仍能在模型交互中完整理解。
4. 检查对话存取、压缩与记忆是否在上下文模块形成连续知识体系。
5. 更新索引和旧链接，保留原有元信息与可运行材料。
6. 验证 JSON、示例对应关系、链接、交互图与 `npm run docs:build`。
7. 检查正文没有引入真实代码、调用地址、具体模型标识或 SDK 接入步骤。

最终验收重点是：知识次序明确、基础能力完整、专题划分适度、例子能够相互对应，且读者不需要在多个模块之间反复跳转才能拼出一个基本功能。
