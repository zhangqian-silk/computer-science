# 学习练习与对照实验

练习用消息、状态、证据和统计检验理解，不要求编写真实接入代码。下列数据均为过程推演或虚构统计；模型实验的设计需实际运行后才能形成性能结论。

---

## 一、模型交互：用户追问与工具回填

已知用户提供配置「端口 8080、超时 30 秒」，模型已经回答端口。用户追问「超时呢？」

任务：写出下一次模型可见的信息，再把场景改为用户只给了文件名、模型需要读取文件。比较两种场景中的调用次数与消息角色。

<details>
<summary>参考分析</summary>

普通追问需要当前有效指令、包含配置的原始 user 消息、此前 assistant 回答及新 user 消息。文件读取场景需要原始问题、assistant 工具调用和与之对应的 tool 结果；没有新 user 消息，也可以发起下一次生成。

调用 ID 将结果关联到实际调用，不是会话 ID。工具参数中的路径只说明读取目标，文件正文需由执行结果提供。

</details>

图片扩展：一张截图显示超时 60 秒，用户问「是否已经运行生效」。区分可见字段、保存状态和运行状态。仅凭截图中的字段值，不能证明后两者。

## 二、上下文：保存与选择

给定历史包含 20 条消息、一个完整工具调用组、用户早期的「只读」约束和一份长日志。假设资料输入预算为 4,000 token。

任务：设计保存范围与发送范围；说明哪类信息不能因位置较早而直接删除。比较最近窗口和「约束 + 摘要 + 近期完整组」。

<details>
<summary>参考分析</summary>

原始历史可独立保存，发送时只选择必要内容。「只读」仍是有效约束；调用组应符合协议关联；长日志可以保留相关段落和回查引用。摘要必须区分已经观察与待执行事项。

评价应使用依赖早期约束、精确数值和近期指代的后续问题，而不只比较输入长度。

</details>

压缩实验设计：固定历史与后续问题，仅改变压缩方法；检查关键事实覆盖、调用组合法性、后续回答、摘要成本及回查次数。此实验可先人工推演，再用重复模型运行验证。

## 三、工具：同一个超时，不同处理

一个只读查询和一个创建记录操作都超时了。任务：分别给出哪些事实已知、哪些未知、能否重试。

<details>
<summary>参考分析</summary>

查询可在预算与工具契约允许时有限重试，但重试读取的可能是新状态。创建操作可能已经发生，应先使用稳定操作标识查询结果，或按服务端幂等契约处理；没有保证时不能盲目再次创建。

超时是等待结果，不等于业务操作明确失败。缺少参数、无权限和无此对象也应分别表示。

</details>

扩展题：工具描述说时间单位为秒，实现按毫秒执行，schema 检查为什么发现不了？因为数据形状相同，语义契约不同。

## 四、流程：两种实现同一目标

目标是「解释配置值及其来源」。任务：画出一个固定读取与解释流程，再画出发现配置覆盖后继续查询的 Agent Loop。

<details>
<summary>参考分析</summary>

Workflow 的读取、检查、生成路径预先定义；Loop 根据观察提出是否检查覆盖来源。两者都可以使用多个模型调用，也都应处理权限不足和预算耗尽。

完成标准应是结论与来源相符，而不是完成预定调用次数。固定流程若已经覆盖所需分支，无需仅为自主性改成 Loop。

</details>

多 Agent 扩展：两名执行者分别读取文档和配置，一人返回旧版本结果。主执行者应检查版本和证据，不能直接把两段摘要拼为最终结论。

## 五、运行时：恢复与取消

任务已向外部系统发出写入，随后进程退出，本地没有回执；用户又发送取消。任务：定义恢复后的状态和允许动作。

<details>
<summary>参考分析</summary>

先记录取消意图并禁止新业务步骤，但仍需确定在途写入是否已发生。可做必要查询或对账，不能把缺回执当作未执行，也不能以恢复为由再次写入。已经发生的效果需说明，是否补偿是另一个决定。

最终状态可体现任务取消与动作结果未知两个维度，不必用一个成功布尔值压平。

</details>

## 六、评测：计算与解释

两个方案处理同一组 20 个任务：共同成功 14 个；仅 A 成功 2 个；仅 B 成功 3 个；都失败 1 个。

任务：计算成功率，说明新版 B 是否可以直接发布。

<details>
<summary>参考分析</summary>

A 为 16/20，即 80%；B 为 17/20，即 85%。但 B 同时修复 3 个、退化 2 个，应检查退化类别、重复运行波动、安全边界和成本。一个小样本总分不能替代发布判断。

</details>

完整对照实验应记录目标、唯一变化变量、固定条件、样例集、评分器、重复次数和任务级结果。预期现象是假设，不是提前写好的结论。

## 七、综合复述

尝试不看正文，连续说明一次任务：

1. 输入怎样组织，模型输出如何读取。
2. 工具如何校验、执行并返回。
3. 用户追问和工具结果怎样进入后续调用。
4. 历史怎样保存与选择。
5. 下一步和终止由谁决定。
6. 如何区分成功、未知、等待和取消。
7. 用什么证据评价任务结果。

能够连续解释这些关系，再进入各个进阶专题；不以背出产品字段和 SDK 调用方式作为学习完成标准。
