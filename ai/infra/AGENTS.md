# AI Infra 写作规范

本文件适用于 `ai/infra/` 子树，并继承仓库根目录和 `ai/AGENTS.md`。

## 页面职责

- `accelerator/`：单设备执行、存储层级、算子、编译与性能分析；
- `distributed/`：设备间通信、Collective、网络拓扑与通信成本；
- `training/`：训练循环、状态分片、并行策略、数据和 Checkpoint；
- `inference/`：请求执行、KV 管理、调度、解码、分布式推理和框架实现；
- `platform/`：部署、路由、容量、可观测性与运行保障；
- `labs/`：可复现实验和综合项目规格，不重复专题原理。

一个页面应从同一层回答一个主要问题。模型公式链接到 `ai/mechanism/` 或 `ai/model/`，通用网络与高可用知识链接到仓库对应页面。

---

## 证据与版本

- 算法来源优先使用论文，框架行为优先使用官方文档与当前源码；
- 框架页顶部标明「概念基线」和「实现核验」，版本变化快的接口不写成永久事实；
- 任何基准数据都必须包含硬件、模型、序列长度分布、并发、精度、命令和统计口径；
- 理论 FLOPs、带宽上界和实测吞吐分开书写；
- CPU 路线用于验证语义、调度、内存与分布式概念，不能替代 GPU Tensor Core、HBM 或 CUDA kernel 的真实性能结论。

---

## 实验规格

未实现的实验统一标记为「实验设计」，不得暗示已经得到实测结果。每个实验至少包含：

- 要验证的假设；
- GPU 路线和可行时的 CPU 路线；
- 自变量、控制变量和观测指标；
- 正确性不变量；
- 预期现象与可能的反例；
- 复现环境记录模板。
