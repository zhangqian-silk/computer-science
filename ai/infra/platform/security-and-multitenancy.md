# 安全与多租户边界

AI 服务的安全边界横跨输入、制品、执行器、缓存和观测系统。模型可以生成任意文本，却不能据此获得资源权限；缓存是输入派生数据，也不能仅因不是原文就被视为公开。先标出谁能读取和修改每一类状态，再选择隔离方式。

---

## 资产与边界

| 资产 | 主要风险 | 基本控制 |
| --- | --- | --- |
| 模型权重/adapter | 未授权读取、篡改 | 制品校验、最小权限、静态加密 |
| Prompt/输出 | 敏感信息泄露 | 传输加密、日志脱敏、保留策略 |
| GPU memory | 跨进程残留或越界 | 可信 Runtime、进程/设备隔离、及时释放 |
| 外部媒体/URL | SSRF、恶意文件、资源耗尽 | 独立下载器、allowlist、大小/类型限制 |
| Tool/代码执行 | 任意外部动作 | 与推理服务分离的授权和沙箱 |
| Metrics/Trace | 高基数内容或 token 泄露 | 不记录原文、受控采样与访问 |

模型生成内容不应被当作可信控制指令。工具执行属于 Agent 的授权边界，不能因为输出符合 JSON 就直接执行。

释放显存不等于清零或完成保密隔离；复用块时必须禁止读取未初始化/越界槽，并按安全域与威胁模型决定清理规则。内容 hash 也不天然匿名，低熵输入可能被枚举。

---

## 多租户资源隔离

租户配额至少覆盖请求、输入/输出 token、在途 KV、adapter cache 和媒体处理。公平调度不能只限制 QPS，因为一个超长请求可能占用远多于短请求的 GPU 时间与 KV。

MIG、独占 GPU、进程隔离和共享 engine 提供不同成本/隔离水平。共享 engine 吞吐高，但 batch、cache 和日志都必须保留租户归属，且不得通过 timing、错误或缓存 key 暴露其他租户内容。

---

## 缓存与日志

跨租户命中相同前缀可能通过延迟差暴露「另一租户是否使用过此输入」。安全域隔离能减少此类信息通道，但会牺牲缓存复用。选择需要基于数据分类与租户契约，不应仅按全局命中率。

外部 URL 获取应限制目的地址和重定向路径，并设置大小、类型和时间预算；输入解析放在受限边界内，不能让模型运行进程承担不受控下载。模型制品也可能包含可执行加载逻辑，可信格式与来源校验和最小权限缺一不可。

本分区的实验只验证可观察的访问拒绝、配额和日志脱敏；GPU 内存侧信道、驱动隔离等不能由 CPU mock 测试证明安全。

Prefix/KV cache 含有输入派生状态。跨租户共享前缀只有在数据分类、租户契约和 key 隔离允许时才考虑；默认按租户或安全域隔离更清晰。

日志优先记录 token 数、hash、版本和错误类型，不记录完整 prompt/输出。若调试确需采样内容，应有显式授权、脱敏、访问审计与到期删除。

---

## CPU 路线

鉴权、配额、租户调度、日志脱敏、恶意媒体和缓存隔离都可以在 CPU mock 服务上测试。GPU memory 隔离和 MIG 需要目标硬件与驱动环境验证。
