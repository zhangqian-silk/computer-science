# 长上下文评估：测量可用长度而非输入上限

长上下文能力不是单个最大长度数字，而是特定任务在不同长度和证据位置上的质量—成本曲面。输入未截断、找出字符串、整合多份证据和追踪状态更新，是逐级不同的能力，评估不能让最简单任务代表全部。

::: info 符号与约定
沿用[数学与符号约定](../foundations/math-notation.md)。$L$ 是上下文长度，$p\in[0,1]$ 是关键证据的相对位置，$\kappa$ 是任务类型，$S(L,p,\kappa)$ 是对应得分；$\gamma_\kappa$ 是任务 $\kappa$ 的最低可接受阈值。本文的「可用长度」要求所有指定位置和任务均达到各自阈值。
:::

---

## 基本实验矩阵

设上下文长度为 $L$，关键证据位置为相对比例 $p\in[0,1]$，任务得分记为：

$$
S(L,p,\kappa)
$$

$\kappa$ 表示任务类型。至少应覆盖：

- 多个长度，包括训练范围内与范围外；
- 开头、中间、结尾等证据位置；
- 多个随机内容与种子；
- 相同总长度下不同数量的干扰项。

只在末尾放一根 needle 会漏掉位置偏差，也容易被特定提示格式优化。

一个最小矩阵可以这样组织：

| 长度 | 证据在 10% | 证据在 50% | 证据在 90% |
| ---: | ---: | ---: | ---: |
| 4K | 多随机样本成功率 | 多随机样本成功率 | 多随机样本成功率 |
| 16K | 多随机样本成功率 | 多随机样本成功率 | 多随机样本成功率 |
| 64K | 多随机样本成功率 | 多随机样本成功率 | 多随机样本成功率 |

每个单元格都应包含不同内容和随机种子，而不是复用同一条 needle。长度要按实际 tokenizer 产生的 token 计数，不能用字符数近似后直接标成模型上下文长度。

## Needle / Passkey 测什么

Passkey 可以从未见随机编号开始，以减小凭参数记忆回答的可能；同时使用多个模板与多个干扰编号，避免模型只学会搜索某个固定标记。把问题和答案在原文中重复很多次会改变难度，应记录插入次数和局部上下文。

在长文本中埋入随机字符串、编号或明确事实，再要求模型复述。它能验证：

- 输入是否被截断；
- 远距离精确检索是否工作；
- 不同位置是否存在明显盲区。

它不能证明模型会比较多份证据、理解叙事或完成复杂推理。随机值和多种模板可减少依赖语料记忆，但任务仍然偏简单定位。

## 从检索升级到整合

更完整的任务应逐级增加要求：

1. 单证据检索；
2. 多证据集合召回；
3. 跨段比较、排序或计算；
4. 追踪实体、状态和时间变化；
5. 在冲突证据中选择带来源支持的结论。

需要报告每一级的失败。单证据检索成功不能排除位置机制对多证据整合的影响，应继续做位置与内容对照；答案正确但引用错误，也不能证明使用了给定证据。

无上下文对照可以判断模型是否凭参数记忆直接答对；打乱证据或加入冲突证据，可以判断模型是否真正使用输入。若有证据与无证据得分几乎相同，单看最终答案无法支持「长上下文被利用」的结论。

## 位置偏差

Lost in the Middle 的关键观察是某些任务和模型对证据位置敏感，尤其不能用首尾成功推断中间也成功。它不是所有模型都有同一 U 型曲线的定律。复现实验应保持内容、总长度与问题不变，只移动证据，再报告随机内容的区间。

模型可能更容易利用开头和结尾，而忽略中间信息。对同一证据做位置轮换并保持其他内容不变，可以隔离位置效应。若调整位置同时改变附近语义或文档边界，结论会混入内容难度。

还应检查证据顺序：把支持与反驳段落交换位置，观察模型是否过度依赖最近内容。

## 成本曲线

测试矩阵只采样有限长度。某长度通过不意味着所有更短或相邻长度自动通过；若要承诺连续区间，应要求已测试区间内各长度点均达标，并说明未测间隔。将单个偶然成功的最长点命名为「稳定支持长度」会夸大结论。

每个长度点同时记录：

- prefill 延迟和吞吐；
- 逐 token decode 延迟；
- 峰值显存与 KV cache；
- 输入 token 费用；
- 准确率相对短上下文基线的变化。

更长窗口若只带来微小质量收益，却显著增加延迟和费用，系统可能更适合检索、分块或摘要。成本是能力边界的一部分。

可以为每类任务预先定义阈值 $\gamma_\kappa$，把可用长度写成：

$$
L_{\mathrm{usable}}
=
\max\left\{L:S(L,p,\kappa)\geq\gamma_\kappa,
\ \forall p,\kappa\right\}
$$

这里的最大值仅在已测试长度集合中求取，位置和任务也指预先定义的测试集合，不是对所有可能输入的数学保证。若集合为空，应报告未达到阈值。$\gamma_\kappa$ 来自任务要求，并附带该长度下的成本约束与统计不确定性。

## 对照与报告

建议至少包含以下对照：

- 相同模型的短上下文与扩长配置；
- 有证据、无证据和冲突证据；
- 全文输入与检索后少量证据输入；
- 原训练长度内性能，检查扩长是否伤害短任务；
- 不同位置机制或主干在相近资源预算下的结果。

位置插值与 ALiBi 见[长上下文位置扩展](../mechanism/long-context.md)，稀疏连接见[稀疏注意力](../mechanism/sparse-attention.md)，状态压缩主干见[状态空间模型](../model/state-space-model.md)。

比较配置时保持提示、任务内容和输出预算一致。上下文变长后若同时允许更长答案、改变 batch 或更换 kernel，延迟差异就包含多项变化。结果应按长度画曲线并给出样本级区间，不用单个最大长度数字概括全部行为。
