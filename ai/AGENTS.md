# AI 目录写作规范

本文件补充仓库根目录的通用规范，适用于 `ai/` 子树。

## 目录边界

- `foundations/`：理解后续主题所需的神经网络基础与方法演化；
- `representation/`：对象如何被编码、训练、比较并用于检索；
- `mechanism/`：可被多个模型复用的计算或参数化机制；
- `model/`：具有完整输入、结构、训练目标与推理接口的模型或模型家族；
- `evaluation/`：指标定义、实验设计、诊断方法与结论边界；
- `agent/`：模型、工具、状态与控制流组成的执行系统。

新增主题前先判断其主要问题属于哪一层。若一个页面横跨多层，应保留一个主问题，其余内容使用最小背景并链接到对应主页面。

---

## 内容组织

- 每篇文档只承担一个明确职责；同一公式或机制只在主页面完整推导；
- 结构由主题决定，不套用固定的「背景—符号—公式—例子—优缺点—小结」模板；
- 开头直接说明研究对象、关键问题与默认版本，不写写作意图或目录说明；
- 先解释决定理解的主干，再补公式、变体和工程约束；符号表仅在确实降低阅读成本时使用；
- 例子应推动推理，不为满足形式要求而添加；
- 对模型的评价必须给出比较对象和条件，避免「更强」「更先进」「广泛应用」等无边界判断；
- 历史页面负责连接演化关系，不重复各专题正文；入口页负责导航，不复述专题结论。

---

## 公式、图与引用

- 全局符号、对象类型与排版遵循 `foundations/math-notation.md`；词表使用 $\mathcal{V}$，Attention Value 使用 $V$；
- 含多组公式的技术页在首次推导前增加简短的「符号与约定」提示，只列该页实际使用的局部符号；
- 同一页面内不让一个符号承担两种含义；确需使用专题惯例时，应改写冲突符号或在首次出现前明确说明；
- 公式前交代问题，公式后解释输入、输出和结论；不设置脱离正文的「公式索引」；
- 机制、架构、数据流或可见性关系优先使用简短结构图；图后必须解释读图结论；
- 原始方法与现代常见实现不一致时，明确标注版本，例如 post-LN / pre-LN、原始 GPT / 现代 decoder-only LLM；
- 参考文献放在文末，只保留正文真正依赖的来源；正文中的历史归属与关键定义应能对应到文末文献；
- 不把博客或产品宣传材料当作基础机制的一手来源。

---

## 质量检查

修改完成后至少检查：页面职责是否唯一、前置知识链接是否正确、术语和符号是否前后一致、相邻页面是否重复展开，以及 `npm run docs:build` 是否通过。
