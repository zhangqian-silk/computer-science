# Embedding：离散对象的连续表示

Embedding 是一个可学习映射，把 token、商品 ID、图像片段等离散对象变成固定维度的实数向量。向量本身没有天然语义；它的几何结构由训练数据、目标函数和模型上下文共同塑造。

::: info 符号与约定
沿用[数学与符号约定](../foundations/math-notation.md)。$\mathcal{V}$ 是离散对象集合，$E$ 是 Embedding 矩阵，$e_i$ 是对象 $i$ 的 one-hot 向量，$v_i$ 是查表得到的稠密向量，$d$ 是向量维度；$\theta$ 表示后续网络参数，$\mathcal{L}$ 表示训练损失，$\eta$ 表示学习率。
:::

---

## 从 one-hot 到查表

设对象集合为 $\mathcal{V}$，one-hot 向量 $e_i\in\mathbb{R}^{|\mathcal{V}|}$ 只有第 $i$ 维为 1。Embedding 矩阵记为：

$$
E\in\mathbb{R}^{|\mathcal{V}|\times d}
$$

对象 $i$ 的向量就是第 $i$ 行：

$$
v_i=E[i]=e_i^\top E
$$

实现中不会真的构造巨大的 one-hot 向量，而是用 ID 直接查表。$d$ 通常远小于 $|\mathcal{V}|$，因此模型获得了一个稠密、可训练的输入接口。

查表解决的是表示形式，不保证相似对象自动靠近。只有当训练任务让两个对象承担相似预测职责时，它们的参数更新才可能形成相近方向。

### 一次查表与梯度累积

假设词表有 4 个对象、向量维度为 2：

$$
E=
\begin{bmatrix}
1.0 & 0.0\\
0.2 & 0.8\\
-0.5 & 0.4\\
0.7 & -0.1
\end{bmatrix}
$$

输入 ID 序列为 $(2,0,2)$，查表结果为：

$$
X=E[[2,0,2]]=
\begin{bmatrix}
-0.5 & 0.4\\
1.0 & 0.0\\
-0.5 & 0.4
\end{bmatrix}
$$

ID 2 出现两次，两处上游梯度都会累加到 $E[2]$；ID 0 的梯度写入 $E[0]$；本 batch 没有访问 ID 1 和 3，它们不会收到直接查表梯度。Embedding 层因此常产生稀疏的行更新，但后续是否使用稀疏优化器取决于框架与模型实现。

## 向量如何获得意义

假设 embedding 后接网络 $f_\theta$：

$$
\hat{y}=f_\theta(E[i])
$$

损失反向传播时，只有当前 batch 中被访问的行收到直接梯度：

$$
E[i]\leftarrow E[i]-\eta\frac{\partial\mathcal{L}}{\partial E[i]}
$$

若「猫」和「狗」经常出现在相似上下文、承担相似标签或与相似样本组成正对，它们会反复收到相似更新；向量邻近性是这种共享训练压力的结果。

训练信号决定几何结构的含义：

| 训练目标 | 被拉近的对象 | 表示更适合 |
| --- | --- | --- |
| 局部上下文预测 | 出现在相似语境中的词 | 词义与句法相似性 |
| 下一 token 预测 | 有助于相同后续预测的上下文 | 生成模型内部表示 |
| 对比学习 | 标注或构造的正样本对 | 检索、匹配、聚类 |
| 分类损失 | 支持相同类别决策的样本 | 特定判别任务 |

因此，不能脱离训练目标讨论「哪种 embedding 最好」。

## 相似度只是一个读出函数

向量常用余弦相似度比较：

$$
\operatorname{cos}(u,v)=\frac{u^\top v}{\|u\|_2\|v\|_2}
$$

若向量已做 $L_2$ 归一化，余弦相似度与点积排序一致。欧氏距离则同时受方向和模长影响。训练使用的打分函数应与部署时的检索度量一致，否则模型优化的空间与系统实际读取的空间不同。

近邻关系可以帮助诊断表示，但不能单独证明模型理解了语义。高频词、数据偏差和表示各向异性都可能造成看似稳定的聚类。具体诊断见[向量表示分析](../evaluation/embedding-geometry.md)。

## 静态表示与上下文化表示

静态 embedding 为每个对象保存一个固定向量：

$$
v_i=E[i]
$$

[word2vec](./word2vec.md) 属于这类方法。它计算便宜、易于缓存，但无法根据语境改变一词多义的表示。

上下文化表示把整段输入送入编码器：

$$
H=f_\theta(x_1,\ldots,x_n),\qquad h_i=H[i]
$$

同一个 token 在不同句子中得到不同的 $h_i$。BERT、GPT 等模型的隐藏状态属于上下文化表示；输入端仍可能有查表 embedding，但最终表示已经混入上下文信息。

需要区分三个层次：

- token embedding：词表查表得到的初始参数；
- token representation：经过上下文编码后的逐位置状态；
- sequence embedding：通过池化、特殊 token 或专门训练得到的句子/文档向量。

最后一类若用于语义检索，需要额外处理池化、对比目标和负样本，见[文本嵌入](./text-embedding.md)。

## 粒度与容量

对象粒度决定词表大小和组合方式。词级表示直观但容易遇到未登录词；字符或子词可以组合新词，却会增加序列长度；图像 patch 和音频帧则把连续信号切成模型可消费的单元。

维度 $d$ 是容量与成本的折中：

- 维度过小会迫使不相干因素共享方向；
- 维度增大会增加参数、存储和检索计算；
- 有效维度还受数据规模、正则化和目标函数限制，不等于名义维度。

Embedding 矩阵的参数量为 $|\mathcal{V}|d$。超大离散词表或推荐系统 ID 表常需分片、量化或哈希，但这些是部署选择，不改变查表映射的定义。

新对象怎样获得 ID 也必须提前定义：

- 文本词表可用字符或子词组合未见单词，避免每个新词都新增参数行；
- 封闭词级词表通常把未登录词映射为 `<UNK>`，不同未见词会共享一个向量；
- 推荐系统中新商品或新用户没有充分交互记录，常需要内容特征、默认向量或在线更新处理冷启动；
- 哈希映射能限制表大小，但碰撞会迫使不同对象共享参数。

这些方案决定模型在未知输入上的行为，不能只在训练数据已经覆盖的 ID 上评估。

## 训练与使用时的角色

训练阶段，Embedding 通常只是更大计算图中的第一组参数。任务损失通过后续网络回传，决定哪些行往哪个方向移动。推理阶段只执行查表，参数不再更新。

不同使用方式读取不同结果：

| 使用方式 | 实际读取的表示 |
| --- | --- |
| 语言模型输入 | 初始 token embedding，随后继续上下文化 |
| 静态词向量检索 | 直接读取并常做归一化的词表行 |
| 句子/文档检索 | 编码器输出经池化后的 sequence embedding |
| 推荐系统 ID 特征 | ID embedding 与其他特征共同进入排序或召回网络 |

将语言模型输入矩阵直接当作句向量空间，或把分类模型的中间状态直接用于余弦检索，都可能偏离原训练目标。部署接口应与训练时实际约束过的表示层级一致。

---

## 表示的边界

Embedding 会继承训练语料中的频率偏差、刻板关联与领域边界。一个适合搜索的空间未必适合分类，一个在通用语料上稳定的空间也可能无法区分专业术语。

评估时应同时观察下游任务与空间诊断：

- 检索任务使用 Recall@K、MRR 或 NDCG；
- 聚类任务检查聚类质量与跨切分稳定性；
- 语义相似度任务检查与人工标注的一致性；
- 公平性与鲁棒性分析检查敏感属性、拼写变化和领域迁移。

向量是模型与系统之间的数值接口，而不是独立于任务存在的语义字典。
