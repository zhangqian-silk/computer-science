# 地图系统

> **摘要**：地图服务的核心能力是「附近查询」（找附近的 POI/司机）、「路径规划」与「实时路况/ETA」。难点在**海量空间数据的索引**、**图上最短路的实时计算**与**高并发低延迟**。本文按「空间索引 → 附近查询 → 路径规划 → ETA 与路况 → 性能治理 → 关键设计要点」推进。

> **关联**：读放大靠[缓存](../../components/cache_component/cache_component.md)；路况事件流靠[消息可靠性](../../base/message_reliability.md)；峰值靠[限流](../../base/high_availability/rate_limiting.md)与[降级](../../base/high_availability/degradation.md)。

## 一、空间索引

把二维经纬度变成可索引的一维键，是空间查询的基础：

- **Geohash**：把经纬度递归二分编码成字符串，前缀相同=地理相近。用字符串前缀就能做范围/附近查询，天然可存进 KV/有序集合。
- **网格/四叉树/R 树**：按区域分格或分层包围盒，适合不同分布密度。

## 二、附近查询

「查附近 3km 的司机/店铺」的标准做法：

1. 计算查询点的 Geohash（精度匹配查询半径）。
2. 取中心格 + 周围 8 格（**九宫格**），避免目标落在边界被漏。
3. 取出这些格内的候选点，再用精确距离（Haversine）过滤 + 排序。

Redis `GEOADD/GEOSEARCH`（底层 ZSet + Geohash）可直接支持。高频移动对象（网约车司机位置）用 Redis 实时更新位置。

## 三、路径规划

路网建模为带权图（节点=路口，边=路段，权=通行时间）。最短路算法：

- **Dijkstra**：单源最短路，正权通用。
- **A***：带启发式（到终点直线距离）的 Dijkstra，剪枝快，适合点到点。
- **分层/预处理（CH、Contraction Hierarchies）**：预计算「捷径」，把长距离路径规划从秒级降到毫秒级，是导航实时性的关键——在线只用不算全图。

离线构图（多源数据清洗融合）+ 在线增量更新（施工、封路）分离。

## 四、ETA 与实时路况

- **路况采集**：海量车辆轨迹上报，经[消息队列](../../base/message_reliability.md)聚合成路段实时速度。
- **ETA 评估**：路径耗时 = 各路段(距离/实时速度) 之和 + 路口延迟；用历史 + 实时 + 模型预测提升准确率。
- **新鲜度权衡**：路况有更新延迟与可见性窗口；旧路况导致 ETA 偏差，需平衡实时性与稳定性。

---

## 五、性能治理

- **瓦片/结果缓存**：地图瓦片、热门路线结果重缓存（读多写少）。
- **热点区域**：CBD、景区等热点区域单独扩容/缓存。
- **降级兜底**：路况服务故障时退回「历史平均速度」估算 ETA，而非报错。

---

## 六、指标体系

- ETA 准确率、路径耗时偏差；
- 附近查询/路径规划 P99 延迟、无结果率；
- 路况更新延迟、缓存命中率。

---

## 七、关键设计要点

- **附近的人**：Geohash/GEO 索引 + 九宫格扫描 + 精确距离过滤。
- **九宫格必要性**：目标可能落在中心格边界，只查一格会漏。
- **路径规划**：Dijkstra/A*，长距离用 CH 等预处理把在线计算降到毫秒。
- **ETA 计算**：路段距离/实时速度求和 + 路口延迟，融合历史与预测。
- **路况故障降级**：用历史平均速度兜底。
- **高频位置更新**：Redis GEO 实时更新 + 过期清理。
